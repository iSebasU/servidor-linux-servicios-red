DHCP Funcionando

DHCP (Dynamic Host Configuration Protocol) asigna automáticamente la configuración de red a los equipos que se conectan. Sin él habría que escribir a mano la IP, la máscara, la puerta de enlace y el DNS en cada computador. El servidor escucha en el puerto UDP 67 y el cliente responde desde el UDP 68.

Cómo funciona: proceso DORA

Avanza paso a paso para ver cómo el cliente XP obtuvo su IP.

Configuración

1. IP fija del servidor +

El servidor DHCP necesita una IP fija dentro de la red que administra. Se configuró por interfaz gráfica (IPv4 manual):

IP: 192.168.1.10   Máscara: 255.255.255.0   Puerta: 192.168.1.1   DNS: 192.168.1.10
2. Interfaz de escucha +

En /etc/default/isc-dhcp-server se indica por qué tarjeta de red atiende el servicio:

INTERFACESv4="enp0s3"
3. Declaración de la subred +
sudo cp /etc/dhcp/dhcpd.conf /etc/dhcp/dhcpd.conf.original
sudo nano /etc/dhcp/dhcpd.conf
subnet 192.168.1.0 netmask 255.255.255.0 {
  range 192.168.1.50 192.168.1.100;
  option domain-name-servers 192.168.1.10, 8.8.8.8;
  option domain-name "serv.dhcpserver.public";
  option routers 192.168.1.1;
  option broadcast-address 192.168.1.255;
  default-lease-time 600;
  max-lease-time 7200;
}
DirectivaSignificado
subnet / netmaskRed que administra el servidor
rangeIPs que puede prestar
domain-name-serversDNS que usará el cliente
routersPuerta de enlace
default / max-lease-timeCuánto tiempo puede usar el cliente la IP antes de renovarla
4. Arranque automático y reinicio +

Se agregó un ajuste para que el servicio espere a la red y se reintente si arranca antes que la interfaz:

/etc/systemd/system/isc-dhcp-server.service.d/override.conf
After=network-online.target
Restart=on-failure
sudo systemctl restart isc-dhcp-server
systemctl status isc-dhcp-server

DNS Funcionando

DNS (Domain Name System) traduce nombres fáciles de recordar, como www.udea.edu.co, a direcciones IP como 192.168.1.10. También hace lo contrario, de IP a nombre, lo que se llama resolución inversa. Se usó bind9, que atiende en el puerto 53. Dominio configurado: udea.edu.co (la guía usa dominio.edu.co).

Prueba el DNS aquí (nslookup simulado)

Escribe un nombre o una IP y presiona Enter. Responde con los mismos registros configurados en el servidor.

C:\> nslookup ...

Configuración

1. Declarar las zonas +

En /etc/bind/named.conf.local se indica de qué dominios es responsable el servidor y dónde están sus datos. La zona inversa se escribe al revés más .in-addr.arpa.

zone "udea.edu.co" {
  type master;
  file "db.udea.edu.co.zone";
};
zone "1.168.192.in-addr.arpa" {
  type master;
  file "db.192.168.1";
};
sudo named-checkconf      # sin salida = sin errores
2. Zona directa (nombre a IP) +

Archivo /var/cache/bind/db.udea.edu.co.zone:

$ORIGIN udea.edu.co.
$TTL 86400
@ IN SOA ns.udea.edu.co. info.udea.edu.co. (
    2026101601 ; serie
    6H ; refresco
    1H ; reintentos
    2W ; expira
    3H ; minimo
)
@     NS    ns
@     MX 10 mail
ns    A     192.168.1.10
mail  A     192.168.1.10
www   A     192.168.1.10
sudo named-checkzone udea.edu.co /var/cache/bind/db.udea.edu.co.zone
zone udea.edu.co/IN: loaded serial 2026101601
OK
3. Zona inversa (IP a nombre) +

Archivo /var/cache/bind/db.192.168.1. Solo se escribe el último número (10), porque el resto ya está en el nombre de la zona.

@   NS   ns.udea.edu.co.
10  PTR  ns.udea.edu.co.
10  PTR  mail.udea.edu.co.
10  PTR  www.udea.edu.co.
sudo named-checkzone 1.168.192.in-addr.arpa /var/cache/bind/db.192.168.1
sudo systemctl restart bind9
Correcciones hechas a la guía +
  • El registro SOA de la guía dice ns.dominio.edu.co.ni.; sobraba el .ni.
  • La guía indica nameserver 192.168.1.1 en resolv.conf, pero el DNS es 192.168.1.10. Ese paso se omitió porque el cliente recibe el DNS por DHCP.
  • La serie se actualizó a la fecha del proyecto (2026101601).

Apache Funcionando

Apache es un servidor web: recibe peticiones de los navegadores por el protocolo HTTP (puerto TCP 80) y les responde con páginas, imágenes o archivos. Esta misma página la está entregando Apache desde la carpeta /var/www/html del servidor.

Configuración

1. Verificar el servicio +
sudo systemctl status apache2

El aviso AH00558 solo indica que no hay ServerName definido; no impide el funcionamiento.

2. Prueba con la página por defecto +

Desde XP se abrió http://192.168.1.10 y http://www.udea.edu.co. Ambas mostraron "Apache2 Ubuntu Default Page", lo que confirma Apache funcionando y el DNS resolviendo el nombre.

3. Publicar el sitio propio +
sudo cp /var/www/html/index.html /var/www/html/index.html.original
sudo nano /var/www/html/index.html

Se reemplazó la página por defecto por este sitio. Apache lo lee en cada petición, así que no requiere reinicio.

4. Control del servicio +
sudo systemctl start apache2     # encender
sudo systemctl stop apache2      # apagar
sudo systemctl restart apache2   # reiniciar
sudo systemctl reload apache2    # recargar configuración

FTP Funcionando

FTP (File Transfer Protocol) sirve para subir y descargar archivos entre un cliente y un servidor. Usa dos conexiones: una de control por el puerto TCP 21, donde viajan los comandos y respuestas, y otra de datos, donde viajan los archivos y listados. Se usó vsftpd (Very Secure FTP Daemon).

Prueba la sesión FTP aquí (simulador)

Simula la sesión hecha desde la consola de XP. Prueba dir, get prueba_servidor.txt, put prueba_cliente.txt, pwd, cd .., help o bye.

Modo activo y pasivo

ModoQuién abre la conexión de datosObservación
Activo (PORT)El servidor se conecta al clienteLo usa la consola de XP. El firewall de Windows puede bloquearlo.
Pasivo (PASV)El cliente se conecta al servidorMás compatible con firewalls; por eso el servidor sugiere "Consider using PASV".

Configuración de vsftpd

Opción en /etc/vsftpd.confValorPara qué sirve
anonymous_enableNONo permite entrar sin usuario y contraseña
local_enableYESPermite entrar con usuarios del sistema
write_enableYESPermite subir, borrar y renombrar archivos
chroot_local_userYESEncierra al usuario en su carpeta; no ve el resto del servidor
allow_writeable_chrootYESPermite el encierro aunque la carpeta tenga escritura
ftpd_bannerBienvenido al servidor FTP de udea.edu.coMensaje de bienvenida propio
local_umask077 (Ubuntu)Los archivos subidos quedan con permiso -rw------- (solo el dueño)
1. Respaldo y configuración +
sudo cp /etc/vsftpd.conf /etc/vsftpd.conf.original
sudo sed -i 's/^#write_enable=YES/write_enable=YES/' /etc/vsftpd.conf
sudo sed -i 's/^#chroot_local_user=YES/chroot_local_user=YES/' /etc/vsftpd.conf
echo 'allow_writeable_chroot=YES' | sudo tee -a /etc/vsftpd.conf
echo 'ftpd_banner=Bienvenido al servidor FTP de udea.edu.co' | sudo tee -a /etc/vsftpd.conf
2. Usuario dedicado y archivo de prueba +
sudo adduser ftpudea
echo "Archivo de prueba del servidor FTP udea.edu.co" | sudo tee /home/ftpudea/prueba_servidor.txt
sudo chown ftpudea:ftpudea /home/ftpudea/prueba_servidor.txt

Se creó un usuario exclusivo para FTP para no exponer la cuenta del administrador.

3. Reinicio +
sudo systemctl restart vsftpd
systemctl status vsftpd
